# Журнал решений

> Почему сделано именно так. Прежде чем «улучшать» что-то из списка — прочитай причину; если она устарела, предложи изменение человеку и допиши сюда новую запись, а не правь старую.

## 2026-09-19 — Next.js-монолит, а не отдельный бэкенд + SPA

Внутренняя админка на ~10 пользователей: UI, API, вебхуки и серверная логика в одном TypeScript-проекте — один деплой, нет контракта фронт↔бэк, типы от Prisma до формы без генерации клиента. Стек лучше всего знаком AI-агентам. Минусы (SSR почти не нужен, Next навязывает кэширование и границу server/client) приняты. Чтобы при необходимости вынести бэкенд, логика живёт в `src/domain` и `src/server`, а не в компонентах. Подтверждено заказчиком в чате.

Рассмотренные альтернативы: Vite SPA + Hono/NestJS (два приложения), Refine/React-admin (упрёмся в рамки на кастомной логике заказов), Django Admin (быстрый CRUD, но слабый UX для менеджеров).

## 2026-09-19 — Prisma 7.10, а не 8.x

На момент старта npm-тег `latest` у `prisma` указывал на `8.0.0-rc.15` (release candidate), а `@prisma/client` — на 7.10.0. Закреплены согласованные стабильные 7.10.0. Обновлять на 8 — после стабильного релиза, вместе с клиентом и адаптером.

Prisma 7 требует driver adapter (`@prisma/adapter-pg`) и `prisma.config.ts`; клиент генерируется в `src/generated/prisma` (не коммитится, генерируется в `postinstall`).

## 2026-09-19 — Better Auth для входа

Нужны свои пользователи (email + пароль), роли и сессии в своей БД, без внешнего IdP. Better Auth даёт это из коробки с Prisma-адаптером. Регистрация отключена (`disableSignUp`) — пользователей заводит ADMIN. Роль и `isActive` — дополнительные поля пользователя, недоступные для ввода с клиента.

## 2026-09-19 — Деньги в целых копейках

Все суммы — `Int` в копейках (`*Kopecks`), никаких float. Исключает ошибки округления в итогах и оплатах. Рубли только на границе UI (`formatRub`, `rublesToKopecks`). Предел Int (≈ 21 млн ₽ на одно значение) для заказов комплектующих достаточен; если понадобится больше — `BigInt`.

## 2026-09-19 — Статусная машина в домене, а не в БД

Переходы и права по ролям — в `src/domain/order/status.ts`, одна таблица. БД хранит только enum. Сервер проверяет каждый переход через `assertTransition`, UI показывает `availableTransitions`. Добавлены переходы сверх первой версии схемы: AWAITING_PAYMENT → IN_PROGRESS (клиент меняет состав) и отмена из PAID/ASSEMBLY только HEAD/ADMIN.

## 2026-09-19 — Журнал OrderEvent = история + аудит

Каждое изменение заказа пишет `OrderEvent` в той же транзакции. Одна таблица закрывает и ленту в карточке, и требование аудита из PRD. Только добавление, без правок и удалений.

## 2026-09-19 — Позиция заказа хранит снимок товара

`OrderItem` копирует sku/name/price на момент заказа; `productId` — необязательная ссылка. Правки каталога и синхронизация с сайтом не меняют старые заказы.

## 2026-09-19 — Inbox для интеграции

Входящий заказ сначала сохраняется сырым в `IntegrationInbox`, потом разбирается. Уникальность `(source, externalId)` даёт идемпотентность. Цель — не потерять заказ при ошибке маппинга; FAILED разбираются вручную в журнале.

## 2026-09-19 — Бизнес-правила по умолчанию без заказчика

Лимит скидки 10%, рабочее время пн–пт 09–18 МСК, нумерация с 1 и др. (PRD, «Бизнес-правила») выбраны без интервью. Реализовывать как настройки/константы в одном месте, чтобы менять без переделки.

## 2026-09-19 — Prisma-скиллы только для Claude Code

`prisma init` поставил скиллы для нескольких агентов через абсолютные симлинки (ломаются в git и на другой машине). Оставлены обычными папками в `.claude/skills/`: `prisma-cli`, `prisma-client-api`, `prisma-database-setup`.
